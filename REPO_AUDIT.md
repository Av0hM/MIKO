# SamOS repository audit — 2026-09-15

Reviewed the current working tree, including existing uncommitted changes, all Rust implementations, manifests, installer/update scripts, and project documentation. No application source or external configuration was changed. This is a broad audit, not a claim that every possible defect has been found. Findings distinguish reachable failures from defects in currently disconnected code and from delivery gaps.

Priority: **P1** = address first (data loss, security boundary failure, build failure, or major broken functionality); **P2** = functional/reliability defect; **P3** = smaller correctness or maintenance problem. File locations refer to this working tree.

## Installation, build, and command execution

1. **P1 — Installer can erase existing desktop configuration.** [install/install.sh:6](/home/sammo/Projects/SamOS/install/install.sh:6) runs `rsync -a --delete` from empty `eww/` and `runtime/` into `~/.config/eww/` and `~/.config/samos/`. With rsync installed, running it against this checkout deletes destination contents. A fresh Git checkout lacks these untracked empty directories and instead fails. `update.sh` invokes the same script. Validate installation assets and preserve existing configuration before enabling this path.

2. **P1 — The workspace does not build/test as a whole.** [plugins/gpu_plugin/src/lib.rs:81](/home/sammo/Projects/SamOS/plugins/gpu_plugin/src/lib.rs:81) duplicates imports from lines 1–5 and `INITIALIZED` from line 7. The plugin is a workspace member, so this blocks ordinary workspace build/test commands, even though targeted daemon builds can succeed. Seven errors reproduced.

3. **P1 — AI app launching executes shell syntax in model arguments.** [ai.rs:666](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/ai.rs:666) interpolates `app_name` into `sh -c "gtk-launch ..."`. An app name containing a shell separator executes additional commands as the daemon user. Confirmation authorizes an apparent app launch, not an unrestricted shell program. The same defect exists in the duplicate helper and MIKO implementation. Pass validated application identifiers as process arguments.

4. **P1 — Automation's command allowlist is bypassable.** [automation.rs:89](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/automation.rs:89) permits an allowed prefix followed by `;` or a newline, then [line 278](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/automation.rs:278) executes the entire string through a shell. The diagnostic test confirms that `notify-send ok; printf audit` and its newline variant pass validation. This is a failed restriction on locally supplied rules, not evidence of a remote entry point.

5. **P1 — Speech text is interpolated into shell code.** [automation.rs:334](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/automation.rs:334) and [miko.rs:401](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/miko.rs:401) place text inside single quotes in `sh -c`. Ordinary apostrophes can break speech, and crafted text can execute commands. MIKO additionally interpolates the voice name. Automation is registered and reachable; the MIKO speech branch is currently disconnected from socket chat. Pipe text to the child process's stdin instead.

6. **P2 — Theme names also enter an unquoted shell command.** [samosctl/main.rs:162](/home/sammo/Projects/SamOS/crates/samosctl/src/main.rs:162) and [ai.rs:703](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/ai.rs:703) interpolate a theme name into a shell invocation. The existence check narrows the trigger but does not make a matching theme filename containing shell characters safe. Spaces also break argument boundaries. Theme paths accept traversal, and AI writes the name into TOML without serialization/escaping.

## AI and voice

7. **P1 — Valid Ollama tool calls fail deserialization.** [ai.rs:66](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/ai.rs:66) requires `ToolCall.id`. Ollama's documented native tool-call format does not require that field. An isolated test reproduces `missing field id`. [miko.rs:64](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/miko.rs:64) also requires it and expects `arguments` as a string instead of an object. See [Ollama's native tool-calling examples](https://docs.ollama.com/capabilities/tool-calling). Generate application confirmation identifiers separately from the response schema.

8. **P1 — Socket chat receives fake zero-valued system state.** [ai.rs:532](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/ai.rs:532) creates `State::default()` for every chat; confirmation does the same at line 549. Neither path receives the daemon's collected metrics. Both the system prompt and `get_system_state` therefore report zero CPU/RAM/battery/disk and empty status strings.

9. **P1 — The confirmation response hides the action being approved.** [ai.rs:619](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/ai.rs:619) stores the call but returns only `CONFIRMATION_REQUIRED:<id>` inside a `Done` response. The declared structured `ToolCall` response is never sent. Clients cannot reliably display the exact tool and arguments from this protocol. Pending calls also have no conversation/client association or expiry.

10. **P1 — Tool continuation loses the user request and remaining calls.** [ai.rs:617](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/ai.rs:617) returns inside the first loop iteration. It drops other calls and recursively sends only a new assistant message and tool result, discarding history and the assistant's tool-call metadata. Confirmed results at line 545 never resume model generation or enter conversation history. Multi-step tasks and follow-up references are consequently unreliable.

11. **P2 — One stalled client or model request blocks all AI clients.** [ai.rs:477](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/ai.rs:477) accepts and processes connections serially. `read_line` has no timeout or length limit; inference has no configured overall timeout; recursive tool execution has no turn limit. An incomplete request can occupy the listener indefinitely, and repeated tool calls can keep inference running indefinitely. All chat history is locked across inference as well.

12. **P2 — Conversation identifiers and retention are incomplete.** [ai.rs:526](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/ai.rs:526) generates a conversation ID when absent but never returns it. Such clients cannot continue that conversation. Histories and abandoned confirmations accumulate without bounds, and failed requests remain in history. A long session also sends its entire retained history to the model.

13. **P2 — Advertised persistent conversation memory is absent from socket chat.** [ai.rs:525](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/ai.rs:525) uses only the in-memory history map. `save_message`, `get_recent_context`, and the alternate persistence helper are not called by the active handler. Restart loses chat context. Existing helper code stores raw content in `summary`; MIKO saves raw messages without generating summaries. Reminder persistence does exist.

14. **P1 — Voice tools are unavailable through the actual chat endpoint.** [ai.rs:155](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/ai.rs:155) registers six non-voice tools. The nine-tool MIKO implementation includes STT/TTS, but no repository caller invokes `MikoModule::chat`, `confirm_tool`, or `deny_tool`. Both modules are registered and write `state.ai`, which obscures this split. This is a backend wiring gap in addition to the documented missing frontend integration.

15. **P2 — MIKO's own confirmation prompt omits its generated ID.** [miko.rs:521](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/miko.rs:521) creates a UUID but formats only literal `confirm <id>` / `deny <id>` instructions. If this API is wired up, its caller cannot obtain the ID from the returned text. Currently latent because the socket does not use MIKO.

16. **P2 — Both MIKO STT paths pass an unexpanded model path.** [miko.rs:389](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/miko.rs:389) and [line 452](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/miko.rs:452) pass `~/.local/...` directly through `Command::args`; no shell expands `~`. Whisper therefore receives a literal, normally nonexistent path. Transcription exit status is also ignored, allowing failures to appear as empty successful transcriptions. Currently latent in the disconnected voice path.

17. **P2 — Voice temporary files and duration handling are unsafe for reliable operation.** [miko.rs:408](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/miko.rs:408) and [automation.rs:339](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/automation.rs:339) reuse fixed `/tmp` output names, retain synthesized audio, and do not check playback success. Recording accepts unbounded/zero duration, and early failures can leave recorded files behind. Any generated transcript sidecars are not cleaned up. Here-strings also assume a shell that supports them despite invoking generic `sh`.

18. **P1 — AI theme switching does not update the daemon's exported theme.** [ai.rs:680](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/ai.rs:680) writes config and reloads Eww, but [samosd/main.rs:33](/home/sammo/Projects/SamOS/crates/samosd/src/main.rs:33) loads config only once and line 58 keeps exporting its old theme. Theme-gated widgets can disagree with newly applied styling until an independent daemon restart.

19. **P2 — AI readiness and logging are misleading.** [ai.rs:762](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/ai.rs:762) always exports `ready`, even with Ollama unavailable or a blocked/failed listener. [Line 611](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/ai.rs:611) writes full model responses, including potentially private generated text/tool arguments, to stderr and thus the service journal. Neither behavior reflects the documented concise, local conversation-memory design.

## Configuration, automation, and daemon lifecycle

20. **P2 — Setting a theme overwrites unrelated configuration.** [samosctl/main.rs:147](/home/sammo/Projects/SamOS/crates/samosctl/src/main.rs:147) resets `monitor` to `focused` and `refresh_ms` to 1000 and discards any other config keys. [ai.rs:694](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/ai.rs:694) duplicates this behavior. Modify only the selected theme in parsed configuration.

21. **P2 — Control commands report success after subprocess failures.** [samosctl/main.rs:46](/home/sammo/Projects/SamOS/crates/samosctl/src/main.rs:46), lines 63, 83, and 157 ignore child exit status. A denied radio toggle, rejected profile, failed restart, or failed Eww reload can still produce success text and exit zero. Missing themes also return `Ok(())`. Similar unchecked results exist in core control and AI tool execution.

22. **P2 — Config errors silently reset settings; monitor is unused.** [samosd/main.rs:17](/home/sammo/Projects/SamOS/crates/samosd/src/main.rs:17) converts read/parse errors into defaults without diagnostics. [config.rs:4](/home/sammo/Projects/SamOS/crates/samos-core/src/config.rs:4) requires all fields, so a partial config silently loses even its valid theme. `refresh_ms=0` is accepted and can cause continuous polling/subprocess churn. `monitor` is never consumed by the daemon/modules.

23. **P1 — Automation repeatedly fires conditions that remain true.** [automation.rs:424](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/automation.rs:424) gates on changes to the entire metric snapshot, not each rule's false-to-true transition or cooldown. CPU fluctuations repeatedly make a still-low battery rule eligible; notifications/app launches repeat, and toggle actions can oscillate. The isolated test reproduces eligibility after an unrelated CPU change. Theme actions additionally invoke a CLI that restarts the daemon, resetting trigger history and potentially creating a restart loop when the condition survives.

24. **P2 — System-based automation evaluates incomplete state.** [samosd/main.rs:60](/home/sammo/Projects/SamOS/crates/samosd/src/main.rs:60) runs modules before filling hostname/time/uptime at lines 63–69. Each tick starts with default state, so those rule fields are empty/zero during evaluation. Separately, [automation.rs:367](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/automation.rs:367) omits `system` from change detection. The isolated test confirms a time-only change is ignored even when supplied a complete state.

25. **P2 — Advertised rule hot reload does not exist.** [automation.rs:419](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/automation.rs:419) loads rules only at initialization. Editing or deleting `rules.json` while the service runs does not change active rules. README explicitly claims hot reload.

26. **P2 — Rule field validation accepts nonexistent fields that can trigger actions.** [automation.rs:81](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/automation.rs:81) validates prefixes, not actual supported fields. `cpu.typo` passes; lookup returns null and `not_equals 50` evaluates true. Both behaviors are reproduced. Operator/value compatibility is also unchecked.

27. **P2 — Adding a rule does not reject an existing rule ID.** [automation.rs:122](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/automation.rs:122) validates a one-element vector, bypassing duplicate detection against existing rules. It saves duplicates that make the next full load fail. Removal also removes every matching duplicate. Mutation precedes persistence, so save failure leaves memory and disk inconsistent. This affects the public API, which currently has no CLI/socket management endpoint.

28. **P2 — One bad optional extension/config can prevent all metrics from starting.** [samosd/main.rs:37](/home/sammo/Projects/SamOS/crates/samosd/src/main.rs:37) propagates plugin-load errors; line 52 propagates module-init errors. One malformed automation rule file, incompatible `.so`, or failed AI database initialization stops the complete daemon instead of disabling the affected feature. The service's restart policy can then repeatedly retry the same permanent failure.

29. **P2 — Synchronous subprocesses can freeze the metric export loop.** [control.rs:11](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/control.rs:11), [workspace.rs:11](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/workspace.rs:11), [visualizer.rs:65](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/visualizer.rs:65), and [automation.rs:267](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/automation.rs:267) block on external commands without deadlines during sequential updates. A hung command or long speech action stalls all metrics. Even normal execution makes actual polling slower than `refresh_ms`, since sleep begins after all work completes.

30. **P2 — Shutdown is unreachable, and the existing shutdown methods would block.** [samosd/main.rs:56](/home/sammo/Projects/SamOS/crates/samosd/src/main.rs:56) has an unconditional loop with no signal-driven exit; module/plugin shutdown is never invoked. [ipc.rs:67](/home/sammo/Projects/SamOS/crates/samosd/src/ipc.rs:67) and [ai.rs:768](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/ai.rs:768) join listeners without stopping `incoming()`. [visualizer.rs:105](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/visualizer.rs:105) joins a reader without stopping cava. Simply calling these methods would not solve cleanup.

31. **P2 — A second daemon instance steals socket paths from the first.** [ipc.rs:26](/home/sammo/Projects/SamOS/crates/samosd/src/ipc.rs:26) and [ai.rs:463](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/ai.rs:463) unconditionally unlink existing sockets. There is no active-server check or single-instance guard. An accidentally launched second daemon can bind those paths while the first remains running and both write the same state file. Manual second-instance execution was not performed.

## Visualizer, metrics, and plugins

32. **P2 — Cava failure leaves stale spectrum permanently.** [visualizer.rs:19](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/visualizer.rs:19) starts cava once. Spawn failure or EOF exits the thread with no restart/reset/health state; after any valid frame the last spectrum is retained forever. Child status is never waited on, allowing a zombie after exit. Cava stderr is discarded, obscuring configuration/input failures.

33. **P2 — The exported spectrum cannot deliver the advertised 60 FPS.** [visualizer.rs:93](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/visualizer.rs:93) copies spectrum only during daemon updates. [samosd/main.rs:74](/home/sammo/Projects/SamOS/crates/samosd/src/main.rs:74) normally sleeps one second. Cava's 60-FPS internal stream therefore becomes roughly one exported frame per second through both state outputs. This is a visible feature limitation, not a request to replace the intentional JSON exporter. Current source/config use 120 bars, despite README claiming 32.

34. **P3 — Track metadata breaks on a normal delimiter character.** [visualizer.rs:67](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/visualizer.rs:67) joins title, artist, and status with `|` and requires exactly three split parts. A title/artist containing `|` makes a playing track appear stopped with empty metadata.

35. **P2 — Network totals are not normalized to elapsed time.** [network.rs:29](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/network.rs:29) exports bytes-per-poll divided by 1024. With a changed refresh interval or slow polling, these values are not the documented KB/s. At a two-second interval, sustained traffic produces about twice the expected per-second value. Idle zeros are intentional and are not the issue. Aggregating every interface can also count the same traffic at multiple virtual-network layers.

36. **P3 — Disk percentage loses precision before calculation.** [disk.rs:37](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/disk.rs:37) truncates total and available bytes to whole GiB before subtraction and percentage calculation. Small filesystems can report materially wrong percentages, and sub-GiB roots report zero usage. Calculate percentage from bytes and round only displayed capacity values.

37. **P2 — WiFi SSID reporting uses the profile name and mishandles escaped colons.** [control.rs:22](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/control.rs:22) queries connection `NAME`, which can differ from the actual SSID. Splitting terse output on every colon also breaks escaped colons in names, causing an active connection to disappear from state. The radio checks assume English command output without fixing locale.

38. **P3 — Some exported fields are placeholders represented as real readings.** [control.rs:150](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/control.rs:150) always reports night light disabled at 4000 K. `State.system.kernel` is never populated anywhere. Consumers and automation cannot distinguish these placeholders from actual device state. Battery/sensor selection limitations are separately acknowledged below.

39. **P1 — Intel GPU sampling can hang the entire daemon if the plugin becomes buildable.** [gpu_plugin/lib.rs:9](/home/sammo/Projects/SamOS/plugins/gpu_plugin/src/lib.rs:9) waits for `sudo -n intel_gpu_top -J -s 1 -o -` to exit. The installed man page confirms `-s` is a millisecond refresh period and the default sample count runs indefinitely. When sudo/tool access succeeds, `.output()` never returns and buffers ongoing output; plugin update runs on the daemon loop. Current compile errors block rebuilding this plugin, so this is a source defect conditional on a usable plugin binary/access. Its line-by-line JSON-object parser also does not handle the tool's multiline stream properly.

40. **P2 — Plugin metadata ownership and failure cleanup are incomplete.** [plugin.rs:24](/home/sammo/Projects/SamOS/crates/samos-core/src/modules/plugin.rs:24) uses metadata pointers without null checks. The supplied GPU plugin allocates those strings via `CString::into_raw`, but the loader never frees them. Initialization occurs before all required symbols are resolved; a later missing symbol unloads without calling shutdown. This is specific ABI handling debt, not a criticism of JSON-over-C-ABI itself.

## Repository delivery and verification gaps

41. **P2 — Build outputs dominate tracked repository contents.** `git ls-files` reports **5,397 tracked build-artifact paths out of 5,449 total** in `target/` and `plugins/gpu_plugin/target/`. [.gitignore](.gitignore) omits those directories. Ordinary builds dirty tracked binaries/caches and produce irrelevant diffs; existing working-tree changes already demonstrate this. Ignoring them alone would not untrack existing entries.

42. **P2 — There is no automated regression coverage or CI.** The targeted Cargo run executes zero tests and the repository has no CI workflows. The formatting check also fails. Critical parsing, confirmation, config preservation, and automation logic have no existing checks, explaining why successful targeted builds can coexist with major broken behavior. The isolated audit tests are diagnostic artifacts, not an installed test suite.

43. **P2 — A fresh checkout cannot reproduce the documented setup.** [install/install.sh](install/install.sh) neither builds/installs binaries nor provides the service, themes, cava config, or required dependencies. README's quick start assumes a pre-existing user service, installed `samosctl`, and external frontend/runtime files. Keeping Eww decoupled is intentional; the gap is missing installation assets/instructions, not their external location. `rsync` was unavailable in the audit environment.

44. **P3 — Current documentation overstates completion and conflicts with source.** README marks voice, memory, automation hot reload, and other features complete despite the failures above; tool/bar/module counts disagree across documents. AGENTS.md says `state.rs` was deleted, but it exists and is exported. The historical handoff's uptime/config/plugin status is stale. README declares MIT, but no license file is tracked. Historical documents should be clearly distinguished from authoritative current status.

## Explicitly excluded from the defect count

- The module → manager → state → JSON → Eww architecture and its intentional full-file rewrite.
- The daemon's thin module re-export wrappers.
- Idle network zeros, hardcoded BAT0 selection, and first-sensor selection: acknowledged limitations, not newly discovered regressions.
- Deliberately deferred RAG, cloud tools, wake-word detection, and other expanded AI scope.
- An assertion that external Eww, Mako, Hyprland, or voice models currently fail: those environments were not comprehensively audited. Only the service unit and cava config were read for context.

Suggested repair sequence: make installation safe; restore the workspace build; remove shell interpolation and repair the automation allowlist; fix the native Ollama schema, state handoff, and confirmation/tool loop; fix automation triggers and theme/config behavior; then address voice wiring, lifecycle, and reproducible setup. Preserve the existing architecture and verify one feature at a time.
